Craft Agents 值得学习的 设计点
它适合作为全栈  Agent 架构样板：不必复刻，但要能解释为什么这样分层。
类型层与业务层分离
@craft-agent/core 放共享类型；@craft-agent/shared 放核⼼业务；应⽤层只消费契约。
多后端 Agent 抽象
Claude 与  Pi 后端并⾏，应⽤不绑定单⼀  SDK ，⽅便做多提供商路由与成本分层。
来源、权限与⾃动化
MCP、REST API 、本地⽂件、会话⼯具、权限模式和⾃动化进⼊统⼀运⾏时，⽽不是散落在  UI ⾥。

做⼀个能演示、能解释架构、能展示迭代过程的项⽬。⼩也可以，但要有业务闭环。

⾄少开⼀个  coding plan 。核⼼是能持续  Plan 、执⾏、验证、复盘。
2. 建项⽬理解  Skill

3. 选 Agent 框架
试 Pi Agent SDK 或  Claude Agent SDK 。把⽂档和示例仓库变成开发  Skill 。

先定 PRD 、架构、数据源、⼯具契约、评测计划和错误处理，再⽣成系统雏形。

如何把项⽬写进简历
不要只写「基于⼤模型实现智能问答」。要写架构、⼯具、评测和优化。明确⽬标⽤户和⾼频任务，不做泛泛的万能助⼿。 ✓
⼯具收窄到业务函数： K 线、市值、 PE 、持仓、新闻、预警。 ✓
写清参数、返回值、失败情况、成本和禁⽌场景。 ✓
把 Skill 做成可维护资产，⽽不是⼀次性提示词。 ✓
建⽴⼩⽽准的评测集，覆盖正常、边界和诱导错误。 ✓
记录失败归因：⼯具、上下⽂、模型、业务规则。 ✓
跑消融实验，判断哪些机制有正贡献。 ✓
对⽐不同模型、提示词、⼯具粒度下的成功率、时延和成本。 ✓

架构表达
写 agent loop 、⼯具注册、会话状态、上下⽂裁剪、权限确认、记忆和错误恢复。
业务表达
写业务场景、关键⼯具、数据源、⽤户路径和约束条件。
结果表达
写评测集规模、成功率、失败类型、成本优化和消融实验结论。
最终⽬标： 不是背框架，⽽是形成判断⼒：看懂核⼼循环，解释⼯具发现、上下⽂管理、权限控制、失败处理和持
续优化。再结合⽬标岗位  JD 做⼀个垂直项⽬，就能得到可展示、可复盘、可写进简历的作品。
